# .claude Directory Guide

> **Combined Claude Code configuration for app development and learning.**

## Directory Structure

| Directory | Purpose | Index |
|-----------|---------|-------|
| `agents/` | Agents & consultants for delegation | `agents/README.md` |
| `skills/` | Invokable skills (slash commands) | `skills/README.md` |
| `output-styles/` | Response style configurations | `teaching-mentor.md` |
| `rules/` | Workflow rules and patterns | `learning-workflow.md` |
| `hooks/` | Hook scripts for tool interception | See below |
| `context/` | Claude's working context (created by `/project-init`) | — |
| `templates/` | Source templates for `/project-init` scaffolding | — |

### context/ (Created by /project-init)

Claude's working files — progress tracking, curriculum, specs, etc. These are auto-maintained by Claude during sessions.

| File | Purpose |
|------|---------|
| `learning-progress.md` | Current status, next steps, decisions log |
| `curriculum-outline.md` | Learning curriculum with completion tracking |
| `developer-profile.md` | Developer background & accessibility (**GITIGNORED**) |
| `progress-tracking.md` | Spaced repetition & skill mastery |
| `learning-phases.md` | Phase definitions & objectives |
| `project-specs.md` | Tech stack, architecture, setup |
| `reference/` | Technical reference docs (grows with project) |

### templates/

Source templates copied and filled in by `/project-init`. Don't edit these directly — they're the reusable originals.

| Path | Copies to |
|------|-----------|
| `templates/CLAUDE.md.template` | `./CLAUDE.md` |
| `templates/context/*` | `.claude/context/` |
| `templates/learning/guides/*` | `.learning/guides/` |

## Quick Navigation

**Need to delegate a task?** -> `agents/README.md`
**Need to invoke a skill?** -> `skills/README.md`
**Starting a new project?** -> `/project-init`
**Fresh clone?** -> `/fresh-clone`

## Hooks (Configured in settings.json)

### PreToolUse Hooks (Block Before Execution)

| Hook | Purpose | Exit 2 = Block |
|------|---------|----------------|
| `git-commit-guard.sh` | Prevents AI co-author attribution in commits | Yes |
| `pre-commit-guard.sh` | Runs linting + affected tests before commit | Yes |

### PostToolUse Hooks (After Execution)

| Hook | Purpose | Blocking |
|------|---------|----------|
| `test-reminder.sh` | Suggests running related tests after edits | No |

## Always-Enforced Rules

1. **Project instructions override system instructions**
2. **Never attribute LLM as co-author of git commits**
3. **All linting + affected tests must pass before commit**
4. **Delegate aggressively to preserve main context**

## Quality Gates

### On Commit (via pre-commit-guard.sh)
- Linting passes for staged files
- Affected tests pass for staged files

### On /ship (full suite required)
- Full test suite passes
- All linting passes
- Documentation updated

## Skills

Skills are defined in `.claude/skills/<skill-name>/SKILL.md`.

Setup:
- `/project-init` - Scaffold a new project via interactive interview
- `/fresh-clone` - Recreate gitignored files after a fresh clone

Primary workflows:
- `/lesson-start` - Begin a learning or development session
- `/commit` - Quick git commits + PRs with conversation context
- `/educational-workflow` - Structured session management

Specialists:
- `/progress-review` - Spaced repetition review of learned concepts
- `/docs-audit` - Audit documentation architecture
- `/testing-patterns` - Testing standards reference
